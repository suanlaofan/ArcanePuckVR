# Arcane Puck VR

一个以魔法学院决斗大厅为舞台的 Three.js + TypeScript + WebXR 桌面曲棍球原型。玩家用单手的符文击槌与 AI 巫师进行一局先得 7 分的对战；在没有头显时，也可以用鼠标和键盘完成完整调试流程。

## 启动

需要 Node.js 20+（建议使用当前 LTS）。

```bash
npm install
npm run dev
```

打开终端显示的本地地址（默认是 `http://localhost:5173`）。

```bash
npm run typecheck  # 仅 TypeScript 检查
npm run test:rules # 得分、金球和球门判定测试
npm run build      # 类型检查并输出生产构建到 dist/
npm run preview    # 预览已构建版本
```

WebXR 需要浏览器允许的安全上下文：`localhost` 可直接用于本机调试；在局域网设备或真实部署上请使用 HTTPS。支持 WebXR 的浏览器会显示进入 VR 的入口，未连接头显时可使用桌面调试输入。

## 一局游戏

1. 在主菜单选择“快速 AI 对局”，再选择学徒、法师或大法师。
2. 玩家和 AI 轮流把奥术圆盘击向对方传送门。圆盘从符文金属边框反弹。
3. 圆盘**完全越过**对方球门线才计分。率先得到 7 分者获胜；若 6:6，则下一分为金球。
4. 停滞、飞出台面或异常卡住的圆盘会自动回到中线。暂停后可以继续、重新开始或回主菜单。

单手扳机可蓄力，松开后下一次接触圆盘会获得更强冲击。蓄力只影响这一次有效击球，不引入技能树或复杂连招。

## 控制方式

| 情况 | 操作 |
| --- | --- |
| VR | 用任一受支持控制器移动击槌；按住扳机蓄力；使用界面按钮开始、暂停或返回菜单。 |
| 桌面调试 | 鼠标在桌面上移动击槌；按住左键蓄力；使用屏幕 UI 选择难度、暂停、重开和返回。 |
| 重置/校准 | 使用 UI 中的“重置视角 / 校准桌面”按钮；VR 中它把球桌锚点重置到当前舒适站位前方。 |

桌面模式是验证玩法的替代输入，摄像机不模拟强制移动或镜头摇晃；VR 模式也不包含玩家移动、强制转向或不适合舒适体验的视觉效果。

## 玩法与实现边界

- 只有单一的快速 AI 对局；没有训练场、联赛、联网、排行、养成或双设备对战。
- 物理由 Rapier 驱动：圆盘、击槌和桌边碰撞使用物理层，画面网格只跟随物理状态。
- 灰盒美术由程序化几何体组成：附魔木桌、金属符文边、发光圆盘、传送门和巫师剪影。这样正式西式奇幻模型不会阻塞玩法迭代。
- 手柄击中圆盘时发出短促、轻量的触觉反馈；代码会优雅降级到没有 haptics 的控制器。

## 架构约定

项目按职责而不是按场景对象切分。以下边界是今后迁移 Unity 时应继续保留的可移植契约：

| 层 | 责任 | 不应包含 |
| --- | --- | --- |
| `src/config/gameConfig.ts` | 球桌尺寸、球门、物理、得分和 AI 参数 | Three.js/Rapier 对象 |
| `src/game/GameRules.ts` | 回合状态、计分、金球、得分判定与重置请求 | 渲染网格、控制器 API |
| `src/game/TablePhysics.ts` | Rapier 刚体/碰撞体、击球冲量、边界与同步快照 | 菜单 DOM、模型选择 |
| `src/game/AiController.ts` | 三档目标位置、反应、容错、拦截/反弹策略 | 直接改画面、改分数 |
| `src/input` | WebXR 手柄姿态、扳机、haptics；鼠标/键盘适配 | 游戏规则判定 |
| `src/render` / `src/game/VisualFactory.ts` | Three.js 场景、光照、占位网格与 VFX | 真实物理和规则真值 |
| `src/ui` / `src/app` | UI 呈现、生命周期、暂停、校准和各层装配 | 具体得分公式 |

规则层读取并输出普通 TypeScript 数据（如位置、速度、比分、比赛状态），而非 `THREE.Object3D` 或 Rapier 句柄。物理层是唯一知道碰撞体的层，渲染层是唯一知道材质/模型的层。这使规则参数和手感标准能够迁移，而不是试图把 Web 运行时代码直接搬到 Unity。

## 参数与资产槽位

所有调参应集中在独立游戏配置中。至少包括：

- `table`: 可玩平面长宽、桌面高度、边框厚度、球门宽/深、发球点和玩家半场边界。
- `puck`: 半径、质量、线性/角阻尼、最大速度、重置阈值和静止超时。
- `mallet`: 半径、接触面高度、质量、最大速度、普通/蓄力击球冲量与蓄力时间。
- `match`: 常规胜分 `7`、金球触发比分 `6:6`、得分和重置延时。
- `ai`: 每个难度的反应时间、目标误差、追球速度、守门偏好、预判与借边权重。
- `comfort`: 桌面前置距离、校准高度和触觉强度/时长。

以下槽位是稳定的替换接口，而不是写死在玩法代码中的文件路径：

| 槽位 | 内容与锚点 |
| --- | --- |
| `TABLE_MODEL` | 球桌可视模型，锚点为可玩桌面中心。 |
| `MALLET_MODEL` | 击槌可视模型，锚点为圆形接触面的中心。 |
| `PUCK_MODEL` | 圆盘可视模型，锚点为几何中心。 |
| `GOAL_MODEL` | 单个传送门模型，锚点为球门线中心。 |
| `ARENA_MODEL` | 决斗大厅环境，锚点为桌面中心在地面的投影。 |
| `VFX_THEME` | 符文、传送门、击球火花、得分和重置效果主题。 |
| `SFX_THEME` | 击球、边框、传送门、得分、菜单和环境声音主题。 |

正式资源替换时，碰撞体仍从 `config` 的简化几何体生成，不从模型网格自动推导。这样艺术升级不会悄悄改变球感。

## 空间、单位与锚点

所有游戏数据使用米、千克、秒、牛顿、弧度和 SI 速度单位。可玩平面的逻辑二维位置为 `(x, z)`：`+X` 是玩家面向 AI 时的右方，`+Z` 指向 AI；`+Y` 始终向上。玩家球门位于负 `Z` 端，AI 球门位于正 `Z` 端。

`TABLE_ANCHOR` 是可玩桌面表面的中心，游戏局部坐标 `(0, 0, 0)` 对应它；世界位置由 `tableAnchor + gameLocalPosition` 得到，且不对规则/物理坐标做比例缩放。击槌接触面中心、圆盘中心、球门线中心都以这一约定定位。详见 [Unity 迁移规范](docs/unity-migration.md)。

浏览器手动检查应覆盖：三档 AI 可开始一局、边框反弹、两侧计分、7 分胜负、6:6 金球、暂停/重开/回菜单、圆盘自动复位、桌面蓄力和 VR 入口（如设备可用）。
